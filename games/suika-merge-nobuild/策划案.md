# Suika Merge No-Build 策划案

> 基于 `suika-merge-nobuild` 当前实现整理。目标是让该项目可作为“同类合成游戏模板”直接复用、改造和扩展。

---

## 一、游戏概述

- **游戏名称**：合成大西瓜（无构建模板版）
- **游戏类型**：2D 物理合成（点击/触控投放）
- **核心体验**：在有限空间中持续投放并合并同级物体，追求更高等级和更高分数
- **单局时长**：约 2~8 分钟（取决于参数配置和玩家熟练度）
- **目标人群**：休闲玩家、短时游玩用户、模板复用开发者

---

## 二、设计

### 2.1 核心玩法机制

- **操作方式**
  - 鼠标或手指在顶部移动，决定投放横向位置
  - 点击/触控屏幕投放当前物体
- **核心循环**
  - 预览下一个物体 -> 投放 -> 物理碰撞 -> 同类型合并升级 -> 分数增加 -> 生成下一个物体 -> 继续投放
- **结束条件**
  - 堆叠超过警戒线并持续超过 `gameplay_warning_hold_ms`，触发 Game Over

### 2.2 子机制列表

1. **随机投放池**
   - 触发：每次成功投放后
   - 效果：基于 `gameplay_spawn_weight_*` 生成下一物体类型
   - 关联：决定局内节奏与策略空间
2. **合并链规则**
   - 触发：碰撞检测到同类型物体
   - 效果：按 `gameplay_merge_to_fruit{N}` 升级成更高类型并加分
   - 关联：核心成长曲线来源
3. **Boss 产出概率**
   - 触发：合并到目标 Boss 类型时
   - 效果：受 `gameplay_boss_merge_chance` 与 `gameplay_boss_max_per_round` 约束
   - 关联：长期目标与高潮反馈
4. **危险预警线**
   - 触发：稳定物体接近 `gameplay_game_over_line`
   - 效果：显示 warning，持续超线则失败
   - 关联：失败压力与节奏驱动
5. **动态世界自适应**
   - 触发：窗口或容器尺寸变化
   - 效果：重建边界、重映射坐标、重算视觉区域
   - 关联：多端一致体验

### 2.3 正反馈循环逻辑

- **即时反馈**
  - 视觉：合并爆效、预览指示器、警戒线闪烁
  - 听觉：掉落音、合并音、成功音、失败音
  - 数值：分数实时增长
- **中期积累**
  - 通过合并链逐步生成更高等级物体
  - 场面复杂度提升，策略性增强
- **长期驱动**
  - 追求 Boss 类型产出和更高分数纪录
  - 参数可扩展为挑战模式（限时、目标分等）

### 2.4 界面交互逻辑

**页面/弹窗列表**

1. **Loading 页**
   - 进入：应用启动后自动进入
   - 退出：资源加载完成自动淡出
   - 功能：显示加载进度
2. **主游戏页**
   - 进入：Loading 完成后进入
   - 退出：浏览器关闭或刷新
   - 功能：主玩法交互、物理渲染、分数显示
3. **Overlay（开始/失败）**
   - 进入：初始状态或失败后
   - 退出：点击按钮（Start/Restart）
   - 功能：局状态切换、简要引导

**游戏内交互元素（9:16 竖屏优先）**

- 顶部：分数区（左上）
- 中上：投放预览（跟随触控横向移动）
- 中央：核心物理游玩区域
- 下方：地面和堆叠区域
- 全屏覆盖层：开始/失败弹层按钮（点击穿透关闭，仅按钮可交互）

## 三、开发

### 3.1 功能点统计

| 模块名称 | 功能描述 | 技术要点 |
|---|---|---|
| 启动模块 | 页面初始化、loading 进度、挂载游戏 | 浏览器 ESM、异步启动 |
| 规则内核（Kernel） | 物理步进、合并判定、得分、失败判定 | Matter.js、固定步长模拟、状态快照 |
| 渲染模块（Renderer） | 场景绘制、输入映射、UI/HUD 更新 | Pixi.js、坐标映射、分层渲染 |
| 音频模块 | 掉落/合并/BGM/失败音效 | HTMLAudio + WebAudio 兜底 |
| 资源加载模块 | 图片纹理预加载、失败降级 | PIXI.Assets、进度回调 |
| 配置系统 | 参数化读取、默认值回退 | `config.json` + `getSetting` |
| 多设备适配 | 等比缩放、安全区、窗口重排 | contain 视口、safe-area、world resize |

### 3.2 代码架构简述

**目录结构（核心）**

```text
suika-merge-nobuild/
  index.html
  src/
    main.js
    config.json
    config.js
    core/
      kernelFactory.js
      contracts.js
    kernels/
      suikaKernel.js
    renderers/suika/
      mountSuikaRenderer.js
      FruitContainer.js
      DropIndicator.js
      HUD.js
      audioFx.js
      fruitAssets.js
    styles/
      suika.css
```

**核心模块划分**

- `kernel`：只做规则和状态推进，不碰 UI
- `renderer`：只做视觉、交互和音效，不写玩法判定
- `config`：统一参数入口，避免硬编码

**渲染引擎与关键技术**

- 渲染：`pixi.js`（CDN）
- 物理：`matter-js`（CDN）
- 运行方式：`index.html` import map + `type="module"`

**资源加载与管理**

- `asset_fruits_*`、`asset_audio_*` 在 `config.json` 声明
- 运行时通过配置键读取
- 通过 `buildAssetMap("asset_fruits_")`、`buildAssetMap("asset_audio_")` 聚合为资源映射
- 加载失败自动降级（空纹理或合成音）

**状态管理方式**

- `dispatch(action)` 驱动 kernel
- `getSnapshot()/subscribe()` 向 renderer 推送状态
- 典型 action：`start_or_restart`、`spawn_fruit`、`tick`、`resize_world`

## 四、美术

### 4.1 整体美术风格

- **风格名称**：清新卡通 + 高饱和休闲手游风
- **主色调**：
  - 主色：明亮黄橙（分数、按钮强调）
  - 辅色：浅蓝与米白（背景与容器）
  - 强调色：红色（危险预警）
- **视觉基调**：
  - 整体偏轻松、治愈、可爱，强调“堆叠成长”的愉悦感
  - 合并瞬间要有明显爆发反馈（亮度/缩放/音效）

### 4.2 UI 设计与配色方案

- 竖屏 9:16，主游玩区占 75%~85%
- 顶部留安全区，分数位于左上，投放预览靠上方中央
- 覆盖层弹窗居中，按钮高度 >= 44px，便于触屏点击
- 按钮推荐圆角胶囊，暖色渐变，文字高对比

## 六、插件扩展与接入规范

本模板是 no-build 形态，插件扩展以“浏览器 ESM + import map + 配置驱动”为主。

### 6.1 已接入插件示例：Matter.js

**引入方式（`index.html`）**

```html
<script type="importmap">
{
  "imports": {
    "pixi.js": "https://cdn.jsdelivr.net/npm/pixi.js@8.17.1/dist/pixi.mjs",
    "matter-js": "https://cdn.jsdelivr.net/npm/matter-js@0.20.0/+esm"
  }
}
</script>
```

**代码使用方式（`src/kernels/suikaKernel.js`）**

```js
import MatterModule from "matter-js";
const Matter = MatterModule.default ?? MatterModule;
```

随后在 kernel 中使用 `Matter.Engine`、`Matter.Bodies`、`Matter.Events` 完成物理模拟、碰撞监听和边界重建。

**配置关联（`src/config.json`）**

- `physics_engine = "matterjs"`
- `physics_step_fixed_delta_ms`
- `physics_material_*`
- `gameplay_gravity`

### 6.2 新增插件通用流程（以动画库/统计库为例）

1. 在 `index.html` 的 import map 新增依赖映射
2. 在对应模块 `import` 该插件（规则类放 kernel，表现类放 renderer）
3. 在 `src/config.json` 新增平铺插件键（如 `plugin_analytics_enabled`）
4. 在逻辑中通过 `getSetting("plugin_analytics_enabled", false)` 读取并启用
5. 只让插件影响其职责层：  
   - 玩法插件 -> kernel  
   - UI/特效插件 -> renderer

### 6.3 推荐的 `config.json` 插件配置结构（可直接添加）

```json
{
  "plugin_matter_enabled": { "value": true, "type": "bool", "label": "Enable matter plugin" },
  "plugin_matter_debug_draw": { "value": false, "type": "bool", "label": "Enable matter debug draw" },
  "plugin_analytics_enabled": { "value": false, "type": "bool", "label": "Enable analytics plugin" },
  "plugin_analytics_sample_rate": { "value": 1, "type": "float", "label": "Analytics sample rate" }
}
```

### 6.4 插件接入注意事项

- no-build 环境优先选择支持 ESM/CDN 的库
- CDN 版本号建议固定，避免线上行为漂移
- 插件开关必须配置化，默认可关闭
- 避免在 renderer 中引入会改写玩法结果的插件逻辑
- 引入后要验证移动端性能（60fps 目标）和首屏加载时长

## 七、模板复用与二次创作建议

1. 第一阶段只改 `config.json`（数值 + 资源）快速出主题版本
2. 第二阶段按需求改 `suikaKernel.js`（玩法）或 `mountSuikaRenderer.js`（交互/UI）
3. 第三阶段若引入新插件，先加开关再灰度验证
4. 每次改动后至少验证：启动、投放、合并、失败、重开、resize 六条主链路
