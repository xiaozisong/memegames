# MBTI No Build 策划案

---

## 一、游戏概述

- **游戏名称**：MBTI No Build
- **游戏类型**：H5 心理测试 / MBTI-like 人格问答
- **核心体验**：通过连续选择题快速完成一轮人格倾向测试，获得可视化结果卡并保存分享
- **单局时长**：约 1~3 分钟
- **目标人群**：轻度休闲用户、社交传播用户、内容运营人员、无构建模板复用开发者
- **运行方式**：无构建，直接通过 `index.html` + 浏览器 ESM 运行

---

## 二、设计

### 2.1 核心玩法机制

- **操作方式**
  - 点击开始按钮进入测试
  - 每题从 4 个选项中选择 1 个
  - 选择后自动进入下一题，无需额外点击“下一步”
- **核心循环**
  - Loading -> Ready -> 答题 -> 维度累计计分 -> 生成结果 -> 展示分享卡 -> 保存图片或重测
- **结果生成方式**
  - 基于 `EI / SN / TF / JP` 四个维度累计分数
  - 每个维度按正负方向映射为对应字母
  - 最终组合成四位 MBTI-like 类型，如 `INFP`、`ENTJ`
- **结束条件**
  - 完成全部题目后自动结算并进入结果页

### 2.2 子机制列表

1. **准备页引导**
   - 触发：应用首次启动或点击重测后
   - 效果：先展示 loading，再进入 Ready 页，按钮点击后正式开始
   - 关联：让单局开始更有仪式感，也便于承接背景图和 BGM 解锁
2. **四维度计分规则**
   - 触发：每次选择选项后
   - 效果：选项携带的 `EI / SN / TF / JP` 分数写入累计状态
   - 关联：决定最终结果类型，是玩法核心规则
3. **自动切题机制**
   - 触发：用户点击某个选项
   - 效果：当前题卡淡出，下一题淡入
   - 关联：提升节奏感，减少操作成本
4. **结果标签聚合**
   - 触发：完成结算并进入结果页
   - 效果：从结果配置中读取 traits，作为标签和分享卡信息的一部分
   - 关联：提升结果表达力与传播性
5. **分享卡导出**
   - 触发：点击“保存图片”
   - 效果：通过 `html2canvas` 将 `#result-card` 导出为 PNG
   - 关联：支撑社交传播与二次分享

### 2.3 正反馈循环逻辑

- **即时反馈**
  - 视觉：题卡切换淡入淡出、选项 hover、进度条推进、结果卡出现
  - 听觉：点击开始后可进入背景音乐播放
  - 结构：每答一题即可看到明确进度变化
- **中期积累**
  - 玩家在答题过程中逐渐形成自我投射和期待
  - 题目主题覆盖能量来源、信息偏好、判断方式、生活节奏等维度
- **长期驱动**
  - 结果卡可保存分享，便于传播
  - 通过更换题库和结果文案，可快速改造成不同主题测试模板

### 2.4 界面交互逻辑

**页面/状态列表**

1. **Loading 页**
   - 进入：应用启动后自动进入
   - 退出：短暂加载完成后自动切到 Ready
   - 功能：建立开始前的缓冲和氛围
2. **Ready 页**
   - 进入：Loading 完成后进入；重测时也回到此页
   - 退出：点击“开始测试”
   - 功能：展示背景、按钮和进入测试的引导
3. **Quiz 页**
   - 进入：点击开始按钮后
   - 退出：答完最后一题
   - 功能：显示当前题目、4 个选项、进度条
4. **Result 页**
   - 进入：全部题目完成后
   - 退出：点击“重新测试”
   - 功能：展示结果分享卡、保存图片、再次测试

**游戏内交互元素（移动端竖屏优先）**

- 顶部：当前题号 + 进度条
- 中央：题目主标题
- 中下：选项列表
- 结果页中央：分享卡
- 结果页底部：保存图片 / 重新测试按钮

## 三、开发

### 3.1 功能点统计

| 模块名称 | 功能描述 | 技术要点 |
|---|---|---|
| 启动模块 | 页面初始化、创建 kernel、挂载 DOM renderer | 浏览器 ESM、无构建启动 |
| 配置系统 | 平铺配置读取、路径映射、默认值回退 | `config.json` + `config.js` |
| 规则内核（Kernel） | 题目聚合、答题记录、维度分数累计、结果计算 | 纯状态机、`dispatch/subscribe` |
| DOM 渲染模块 | Loading / Ready / Quiz / Result 四阶段页面输出 | 原生 DOM API、组件拆分 |
| 题目交互模块 | 选项点击、切题动画、进度更新 | 无框架组件、CSS 动画 |
| 结果分享模块 | 结果卡渲染、标签生成、图片导出 | `html2canvas`、固定卡片尺寸 |
| 音频模块 | 背景音乐创建与点击后播放 | `Audio`、用户手势解锁 |
| 多设备适配 | 全屏容器、安全区、移动端布局 | `100dvh`、safe-area、响应式 CSS |

### 3.2 代码架构简述

**目录结构（核心）**

```text
MBTI-nobuild/
  index.html
  README.md
  SKILL.md
  策划案.md
  src/
    main.js
    config.json
    config.js
    core/
      kernelFactory.js
      contracts.js
    kernels/
      mbtiKernel.js
    renderers/dom/
      mountDOMRenderer.js
      DOMRenderer.js
      components/
        PreparationView.js
        QuestionCard.js
        OptionItem.js
        ResultView.js
      domui/
        designTokens.js
        theme.js
```

**核心模块划分**

- `kernel`：只做题目流程、计分和结果推导，不碰 UI
- `renderer`：只做 DOM 结构、样式、动画、媒体和导出，不写玩法判定
- `config`：统一参数和内容入口，避免硬编码

**渲染与关键技术**

- 渲染：原生 DOM API
- 样式：运行时注入 CSS
- 导出：`html2canvas` 动态加载
- 运行方式：`index.html` + `<script type="module">`

**状态管理方式**

- `dispatch(action)` 驱动 kernel
- `getSnapshot()/subscribe()` 向 renderer 推送状态
- 当前典型 action：
  - `select_option`
  - `restart`

### 3.4 关键状态流说明

- **初始化**
  - 创建 kernel
  - renderer 挂载后进入 loading
- **题目阶段**
  - snapshot 提供当前题目、进度、是否完成
  - 用户点击选项后，先播放切题动画，再派发 `select_option`
- **结算阶段**
  - 最后一题完成后，kernel 基于四维度组合结果类型
  - renderer 切换到结果页并渲染分享卡
- **传播阶段**
  - 用户点击保存图片
  - 结果卡导出为 PNG，用于社交传播

## 四、产品价值

### 4.1 用户价值

- 提供低门槛、短时长的自我测试体验
- 通过轻量结果卡满足“被解释”和“被表达”的社交需求
- 通过高颜值分享卡增强截图传播意愿

### 4.2 业务价值

- 适合作为活动页、品牌测试页、人格互动页模板
- 题库、结果、背景、音乐都可配置，复用成本低
- 无构建方案部署简单，适合快速试验和内容投放

### 4.3 模板价值

- 保持 `core + kernels + renderers + config.json` 分层，便于 AI 和人工协作修改
- 同时覆盖答题页和结果分享页，适合作为“UI 类 H5 模板”
- 平铺配置结构便于运营与策划直接管理内容

## 六、总结

`MBTI-nobuild` 当前已经不是单纯的问答 Demo，而是一套完整的 H5 心理测试模板：

- 前段有准备页承接进入
- 中段有答题节奏和切题反馈
- 后段有结果分享卡和保存图片能力

它适合继续往“活动互动模板”“心理测试模板”“品牌传播问答页”三个方向延展。
