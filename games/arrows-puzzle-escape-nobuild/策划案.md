# 释放虫虫 策划案

---

## 一、游戏概述

- **游戏名称**：释放虫虫
- **游戏类型**：2D 休闲解锁解谜 / 层叠遮挡消除
- **核心体验**：观察虫身遮挡关系，优先释放最上层可点击虫头，逐步拆开整片虫阵
- **单局时长**：约 1~4 分钟
- **目标人群**：轻度休闲玩家、短时触屏用户、喜欢“看关系再操作”的解谜玩家
- **平台与交互**：移动端竖屏优先，支持 H5 触控与桌面端点击

---

## 二、设计

### 2.1 核心玩法机制

- **操作方式**
  - 玩家点击单只虫子的头部进行交互
  - 只有当前未被遮挡的虫子可以被成功释放
- **核心循环**
  - 观察层级 -> 点击虫头 -> 若 blocked 则收到摇头反馈 -> 若可释放则播放退场动画与音效 -> 更新遮挡关系 -> 继续拆解
- **胜利条件**
  - 当前关卡全部虫子移除后通关
- **失败 / 中断状态**
  - 当前版本没有传统失败结算
  - 错误点击不会扣分，只会返回 blocked 提示与头部摇摆反馈

### 2.2 子机制列表

1. **遮挡判定机制**
   - 触发：玩家点击任意虫头时
   - 规则：若该虫任意身体段被更上层虫身覆盖，则该虫 blocked
   - 关联：是核心解谜约束

2. **层级排序机制**
   - 触发：关卡生成后、虫子移除后
   - 规则：每只虫按 `zIndex` 排序，越上层越优先遮挡下层
   - 关联：决定谁可先被释放

3. **动态关卡生成机制**
   - 触发：进入关卡、重开、下一关
   - 规则：运行时随机生成虫子数量、路径长度、分布与重叠
   - 关联：保证重复可玩性

4. **四象限覆盖机制**
   - 触发：关卡生成初期
   - 规则：优先保证四象限都有足够起始覆盖，避免虫阵集中在单侧
   - 关联：提升版面均衡与视觉完整度

5. **Bezier 软管路径机制**
   - 触发：worm 渲染时
   - 规则：虫身使用平滑 Bezier 曲线而非硬折线
   - 关联：强化“软体虫”视觉识别度

6. **即时反馈机制**
   - 触发：blocked 或成功释放时
   - 规则：
     - blocked：头部左右摇摆
     - remove：播放退场动画、粒子效果、unblock 音效
   - 关联：形成明确操作反馈

### 2.3 正反馈循环逻辑

- **即时反馈**
  - 视觉：虫头摇摆、虫身退场、粒子爆散
  - 听觉：释放音效、背景音乐
  - 认知：玩家立刻知道“这只可以移除”还是“它还被压住”

- **中期积累**
  - 随着上层虫子被移除，更多下层虫子从 blocked 变为可点击
  - 场面从拥挤逐步变干净，形成明显解锁快感

- **长期驱动**
  - 关卡数逐步增加
  - 每关虫子更多、结构更密、路径更长，推动玩家持续挑战

### 2.4 界面交互逻辑

**页面 / 弹层列表**

1. **开始弹层**
   - 进入：首次进入游戏
   - 退出：点击开始按钮
   - 功能：说明目标与基础规则

2. **主游戏页**
   - 进入：开始后进入
   - 功能：展示虫阵、接受点击、播放反馈

3. **成功弹层**
   - 进入：当前关虫子全部移除
   - 退出：点击按钮进入下一关；最后一关点击后重新开始
   - 功能：通关反馈与进度推进

4. **提示型失败弹层 / 文案提示**
   - 进入：blocked 反馈时按当前状态系统展示
   - 功能：提醒玩家先解锁上层虫子

**游戏内交互元素（9:16 竖屏优先）**

- 顶部中央：标题与副标题
- 中部主体：满屏 worm board 区域
- 全屏覆盖层：开始 / 成功 / 提示 overlay
- 主要按钮：开始、重开、下一关

### 2.5 难度曲线设计

- **Level 1**
  - 以较高虫量直接建立“满屏虫阵”印象
  - 主要训练玩家理解“看层级，不看路径顺序”

- **Level 2~5**
  - 逐步增加虫子数量
  - 重叠增多，局部判断压力提升

- **Level 6~10**
  - 虫阵更密
  - 路径弯曲更复杂
  - 上下层交错更明显，要求更强的局部解锁规划

## 三、开发

### 3.1 功能点统计

| 模块名称 | 功能描述 | 技术要点 |
|---|---|---|
| 启动模块 | 页面初始化、挂载 kernel 与 renderer | 浏览器 ESM、`main.js` 启动 |
| 配置系统 | 平铺配置读取、`value/type/label` 解析 | `config.json` + `config.js` |
| 规则内核 | action 分发、关卡推进、snapshot 生产 | `arrowsPuzzleKernel.js` |
| 关卡生成模块 | 随机关卡、虫量增长、四象限覆盖、分布平衡 | `LevelGeneratorSystem.js` |
| 数据系统 | 虫子创建、层级排序、占用构建、遮挡收集 | `WormSystem` / `LayerSystem` / `OccupancySystem` / `BlockSystem` |
| 流程系统 | blocked/remove 判定、通关判断、run 创建 | `GameFlowSystem.js` |
| SVG 渲染模块 | 棋盘容器、worm 绘制、DOM UI、动画 | `SvgGameRenderer.js` 等 |
| 输入模块 | pointer 事件到 worm 触发映射 | `InputSystem.js` |
| 音频模块 | BGM 与 unblock 音效播放 | `SvgGameRenderer.js` + HTMLAudio |

**核心模块划分**

- `kernel`：只做规则推进、关卡切换、snapshot 输出
- `systems`：拆分具体规则职责，如生成、排序、占用、阻挡、流程
- `renderer`：只做 SVG/DOM、动画、样式、音频、UI
- `config`：统一参数入口，避免硬编码

**渲染引擎与关键技术**

- 渲染：原生 SVG + DOM
- 动画：Web Animations API + `requestAnimationFrame` 风格工具
- 路径：Bezier 平滑曲线
- 运行方式：`index.html` + `type="module"`

**状态管理方式**

- `dispatch(action)` 驱动 kernel
- `getSnapshot()/subscribe()` 向 renderer 推送状态
- 典型 action：
  - `start_or_restart`
  - `restart`
  - `trigger_worm`
  - `complete_run`

## 四、美术

### 4.1 整体美术风格

- **风格方向**：白底极简 + 软糖/软管质感 + 高饱和虫身配色
- **视觉关键词**：明亮、轻快、可触摸、柔软、层叠、清爽
- **材质感受**：虫身像半透明橡胶糖条，头部有轻微高光，overlay 面板简洁不抢戏

### 4.2 UI 设计与配色方案

**基础配色**

- 背景底色：纯白或浅暖白
- 主文字：深灰蓝
- 次级文字：中灰
- 主强调色：亮青蓝
- 成功色：亮绿色
- 失败提示色：莓红或暖红

**界面布局**

- 顶部：标题与副标题居中
- 中央：大面积游戏板，尽量被虫身填满
- 中层：worm SVG 为主要视觉主体
- 上层：开始 / 通关 / 提示 overlay
- 按钮：圆角胶囊按钮，边框清晰、按下有压感

### 4.3 美术素材需求列表

1. **背景图**
   - 1 张可选背景图，支持替换纯色背景

2. **worm 视觉素材**
   - 当前可纯程序绘制，无需必须外部图片
   - 若升级可补充：
     - 虫头表情贴图
     - 更强的高光遮罩

3. **UI 素材**
   - 当前按钮、面板、文字均可纯 CSS/SVG 实现
   - 可选补充：
     - 通关徽章
     - 轻量粒子贴图

## 五、音乐

### 5.1 总体音乐氛围

- 节奏上应轻松、清爽、不要过度刺激
- 适合短局循环，避免复杂旋律抢占注意力
- blocked 与 unblock 的听觉反馈要明显区分

### 5.2 BGM 列表

1. **主局内 BGM**
   - 风格：轻电子 / 清新木琴 / 轻敲击
   - 情绪：放松、明亮、持续但不喧闹
   - 触发：游戏开始后循环播放

2. **通关强化 BGM（可选后续扩展）**
   - 风格：短促庆祝片段
   - 情绪：轻庆祝，不打断整体节奏

### 5.3 音效列表

| 音效事件 | 当前状态 | 设计建议 |
|---|---|---|
| 点击可释放 worm | 已支持配置 | 短促、清脆、有“抽出”感觉 |
| 点击 blocked worm | 当前主要靠视觉反馈 | 可后续补轻微“闷住”提示音 |
| 通关完成 | 可后续扩展 | 一段简短成功音 |
| 按钮点击 | 可后续扩展 | 轻量 UI click |

## 六、后续可扩展方向

1. 增加 blocked 专属音效与更细的层级提示
2. 增加主题皮肤，如草地、糖果、海底、花园
3. 增加限时模式、步数模式、目标释放模式
4. 增加特殊虫种，如双头虫、锁定虫、一次性虫
5. 增加关卡目标差异，而不只依赖数量增长
