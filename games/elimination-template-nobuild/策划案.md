# elimination-template-nobuild 策划案

## 1. 项目概述

`elimination-template-nobuild` 是一套面向移动端休闲游戏的放置消除模板，当前内置玩法为：

- 方块放置
- 行列消除
- gem 收集目标
- 分数达成

本模板当前对应的是一款 `Block Placement + Line Clear` 风格产品原型。  
其目标不是承载复杂长线系统，而是提供一套可直接运行、视觉完成度较高、参数可配置的放置消除基线方案。

关键词：

- 移动端
- 轻规则
- 强反馈
- 高辨识度霓虹科幻视觉
- 配置驱动

---

## 2. 产品定位

### 2.1 目标用户

- 喜欢轻量拼块放置与消除反馈的休闲用户
- 偏好短局、即时反馈、低学习成本的移动端用户
- 对视觉氛围、拖拽手感、清屏快感较敏感的用户

### 2.2 产品目标

- 在 3 秒内让用户理解“拖拽方块到棋盘，填满行列即可消除”
- 在单局内持续制造“放置收益、清线收益、目标推进”三层动机
- 用高亮 HUD、宝石材质、粒子与扫描光束建立商业休闲游戏感

### 2.3 单局特征

- 开局直接可玩
- 单次操作为拖拽放置
- 规则单纯，但每步存在空间规划
- 既追求即时清线，也追求长期目标达成

---

## 3. 核心体验目标

本模板当前要表达的核心体验不是“复杂策略”，而是以下四点：

1. 放下去要爽  
   方块落位需要有吸附感、贴合感和明确的成功反馈。

2. 清掉时要强  
   行列消除必须伴随明显的光效、粒子、文本或节奏变化，形成清屏奖励。

3. 目标推进要可见  
   gem 收集与分数增长要在 HUD 中持续反馈，用户能明确知道自己离胜利还有多远。

4. 危险状态要可感知  
   当可用落点变少时，需要通过扫描光束等视觉信号提前制造压力。

---

## 4. 核心循环

当前真实实现对应的单局循环如下：

1. 开始游戏，显示棋盘、分数、规则提示与 3 个待放置方块。
2. 玩家从底部托盘拖拽一个方块到棋盘。
3. 系统判定该位置是否合法：
   - 合法：允许放置并吸附落位
   - 非法：给出明显的失败提示，不结算
4. 放置成功后，立即结算：
   - 按已放置单格数量增加基础得分
   - 检查是否形成完整行或完整列
5. 若触发清线，则继续结算：
   - 清除满行 / 满列
   - 增加清线得分
   - 统计被清除的 gem
   - 推进 gem 目标进度
6. 若本轮 3 个方块全部用完，系统生成下一组 3 个方块。
7. 系统检查当前是否胜利，或是否已无任何可放置方案。
8. 用户继续循环，直到胜利或失败。

这个循环同时驱动三条体验线：

- 即时线：放置与清除
- 成长线：分数累计
- 目标线：gem 收集

## 5. 玩法规则

### 5.1 棋盘

- 默认棋盘尺寸：`8 x 8`
- 支持预填充初始格子
- 某些格子可预置或运行时携带 gem
- 棋盘上的每个格子只有两种核心状态：
  - 空
  - 已占用

### 5.2 方块来源

- 每轮默认提供 `3` 个可放置方块
- 方块从 shape 池中随机生成
- 当前不支持旋转
- 方块颜色来自默认颜色池或自定义材质表现

### 5.3 放置规则

玩家将底部方块拖拽到棋盘上，满足以下条件才可放置：

- 不越界
- 不与已有格子重叠

若不满足条件，则判定为非法位置，不发生落位和得分。

### 5.4 清除规则

当任一整行或整列被填满时，立即触发消除：

- 支持单行、单列清除
- 支持多行、多列同时清除
- 清除后对应格子恢复为空位

### 5.5 gem 规则

- gem 会附着在部分格子上
- gem 既可以出现在初始预填充格子，也可以在新生成方块的单元格中随机出现
- 当携带 gem 的格子被清除时：
  - 该 gem 计入目标进度
  - 同时产生额外 gem 得分
  - 触发飞向 HUD 的反馈动画

### 5.6 回合推进

- 当前一组 3 个方块全部使用后，系统立即补充下一组 3 个方块
- 每次成功放置都会增加已使用步数

---

## 6. 分数系统

当前实现包含三段式得分：

### 6.1 放置得分

每成功放置一个方块，按该方块包含的单格数量累计基础分。

默认配置：

- `gameplay_scoring_per_cell = 10`

### 6.2 清线得分

每消除一条完整行或完整列，获得一次清线分。

默认配置：

- `gameplay_scoring_per_line = 120`

### 6.3 gem 得分

每清除一个 gem，额外获得 gem 分数。

默认配置：

- `gameplay_scoring_per_gem = 60`

### 6.4 分数意义

分数在当前产品中承担两个功能：

- 即时奖励反馈
- 胜利条件组成部分之一

---

## 7. 胜利与失败条件

### 7.1 胜利条件

当前实现的胜利判定是“双条件同时满足”：

1. 所有 gem 目标均已完成
2. 当前分数大于等于目标分数

默认目标分：

- `gameplay_scoring_target_score = 3000`

这意味着：

- 只完成 gem 目标，但分数不足，不算胜利
- 只达到目标分，但 gem 未达成，也不算胜利

### 7.2 失败条件

当当前托盘中的任意剩余方块都找不到合法放置位置时，立即失败。

换句话说：

- 不是“棋盘填满才失败”
- 而是“当前可操作空间耗尽且没有任何可落子方案时失败”

### 7.3 危险状态

当前实现还定义了危险状态，用于强化失败前压力感：

- 当游戏已开始
- 且尚未结束
- 且当前所有剩余方块的合法落点总数大于 0 且小于等于 2

此时进入危险阶段，并配合扫描光束等表现强化提醒。

## 8. 视觉基线

### 8.1 总体风格

当前产品的视觉基线为：

- `Neon`
- `Sci-Fi`
- `Dark Glass`

目标不是朴素网页 UI，而是具备移动端休闲商业质感的发光霓虹拼块界面。

### 8.2 背景

背景采用“深色氛围 + 聚焦玩法区域”的策略：

- 默认以深色渐变为基底
- 支持图片、gif、视频、音频资源作为背景媒体
- 当使用视觉类背景媒体时，背景以资源本身为主
- 通过全屏蒙层压暗环境，突出 HUD、棋盘和托盘

### 8.3 HUD

HUD 结构为顶部双层信息区：

- 第一层：`SCORE`、`BEST`
- 第二层：`RULE`

视觉要求：

- 半透明软玻璃面板
- 蓝紫青系 glow
- 强调分数与规则提示的可读性
- 在窄屏设备上保持清晰分层

### 8.4 棋盘

棋盘是视觉中心，要求：

- 居中偏下布局
- 深色底板
- 圆角
- 弱边界、弱网格线
- 允许通过背景媒体增强材质层次

棋盘的视觉定位不是“表格”，而是“承载宝石放置的主战场”。

### 8.5 方块 / 宝石

方块当前采用宝石化表达：

- 高饱和配色
- 玻璃 / 宝石层次
- 发光边缘
- 明暗过渡
- 放置、清除、拖拽时具有明显状态差异

当未指定自定义材质媒体时，系统默认使用颜色池生成宝石风格 block。

### 8.6 危险反馈

为了强化“快要无路可走”的压迫感，当前产品在危险阶段引入扫描光束表现。  
该效果用于传达“局势紧张”，而不是替代实际规则提示。

---

## 9. 交互与动效基线

### 9.1 拖拽

- 支持拖拽 ghost
- 支持落点投影
- 合法位置与非法位置有明确视觉区分

### 9.2 放置反馈

- 吸附落位
- 缩放与震动反馈
- 成功放置后立即切换至下一步决策

### 9.3 消除反馈

- 支持清线动画
- 支持多行 / 多列联动
- 支持粒子爆炸
- 支持 `COMBO` 文本强化

### 9.4 gem 反馈

- 被清除的 gem 会向 HUD 目标位置飞行
- 反馈目标是让“目标推进”可视化，而不是只在数值上增长

### 9.5 开局与结束

- 开局通过 overlay 进入主局
- 胜利与失败都会展示明确的结果 overlay
- 结束态支持再次开局

## 10. 内容构成

### 10.1 shape 库

当前基础 shape 包括：

- `single`
- `line2`
- `line3`
- `line4`
- `L`
- `square`
- `T`

并支持别名归一化：

- `line -> line3`
- `square2 -> square`
- `L3 -> L`
- `T4 -> T`

### 10.2 gem 类型

当前 gem 目标与表现支持多种颜色类型。  
在当前默认配置中，已有两组目标：

- `red`
- `blue`

### 10.3 默认配色

当前 block 主色池以高亮霓虹色为基线，可用于形成明显的区分度与发光层次。

## 11. 配置模型

本策划案只描述“产品参数如何表达”，不展开工程实现细节。

### 11.1 表达方式

当前配置模型采用平铺 key：

```json
"theme_primary": {
  "value": "#33BDFF",
  "type": "color",
  "label": "主色"
}
```

说明：

- `value`：当前参数值
- `type`：参数类型
- `label`：中文显示名称
- 当前颜色字段默认优先使用 `oklch(...)`
- 只有在目标颜色不便于直接用 `oklch(...)` 表达，或需要兼容现成历史色值时，才退回 `#hex`、`rgb(...)` 或 `hsl(...)`

### 11.2 列表型配置表达

旧式数组字段已经不再作为当前基线。  
初始棋盘、shape 池、gem 目标、颜色池统一改为“平铺序号字段”表达。

正确表达方式如下：

#### 初始棋盘格子

- `gameplay_initial_board_cell_1_row`
- `gameplay_initial_board_cell_1_col`
- `gameplay_initial_board_cell_1_color`
- `gameplay_initial_board_cell_1_gem_type`

#### shape 池

- `gameplay_shape_1`
- `gameplay_shape_2`
- `gameplay_shape_3`

#### gem 目标

- `gameplay_gem_target_1_type`
- `gameplay_gem_target_1_count`
- `gameplay_gem_target_2_type`
- `gameplay_gem_target_2_count`

#### 默认颜色池

- `theme_piece_color_1`
- `theme_piece_color_2`
- `theme_piece_color_3`
- `theme_piece_color_4`

## 13. 参数含义摘要

### 13.1 决定局面结构的参数

- `gameplay_board_rows`
- `gameplay_board_cols`
- `gameplay_rules_bag_size`
- `gameplay_shape_<n>`
- `gameplay_initial_board_cell_<n>_*`

这些参数决定用户每一步面对的空间结构与决策密度。

### 13.2 决定目标压力的参数

- `gameplay_gem_target_<n>_*`
- `gameplay_gem_spawn_chance`
- `gameplay_scoring_target_score`

这些参数决定用户是更偏向清线刷分，还是更偏向目标收集。

### 13.3 决定爽感节奏的参数

- `gameplay_scoring_per_cell`
- `gameplay_scoring_per_line`
- `gameplay_scoring_per_gem`

这些参数决定单步奖励、清屏奖励与目标奖励的相对权重。

### 13.4 决定视觉氛围的参数

- `theme_background_*`
- `theme_board_*`
- `theme_hud_*`
- `theme_block_*`
- `theme_piece_color_<n>`

这些参数共同决定当前产品呈现的是“深色霓虹玻璃感”还是其他视觉方向。

## 14. 当前版本边界

当前策划案对应的版本边界如下：

- 单玩法模式
- 单棋盘目标循环
- 无角色成长
- 无关卡地图
- 无经济系统
- 无商城系统
- 无任务系统
- 无社交系统

它是一套完整的“单局放置消除”原型，而不是重运营产品框架。

---

## 15. 验收标准

若一份改造后的内容仍声称基于当前模板，则至少应满足以下产品标准：

1. 用户能直接理解“拖拽放置、填满清除”的主玩法。
2. 放置、清线、目标推进三层反馈同时成立。
3. 胜利条件与失败条件明确且互不冲突。
4. HUD、棋盘、托盘在移动端尺寸下层次清晰。
5. 背景、方块、清线反馈具备统一视觉风格。
6. gem 目标不是摆设，能在局内持续驱动决策。
7. 配置表达与当前平铺 key 模型一致，不再回退到旧数组字段。

---

## 16. 总结

`elimination-template-nobuild` 当前对应的是一款以“放置决策 + 清线爽感 + gem 目标推进”为核心的移动端休闲消除产品原型。

它的真实产品特征可以概括为：

- 规则轻
- 反馈强
- 视觉亮
- 单局清晰
- 参数可控

在此基础上，后续可以继续衍生出更多放置消除变体，但本策划案所描述的基线，必须始终与当前模板的真实实现保持一致。
