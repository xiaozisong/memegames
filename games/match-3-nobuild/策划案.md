# match-3-nobuild 策划案

## 1. 项目概述

`match-3-nobuild` 是一套面向移动端休闲游戏的无构建 Match-3 模板，当前真实运行内容已经包含：

- 相邻交换
- 3 消及以上匹配
- 连锁消除
- 掉落与补珠
- 多目标收集
- 通关进入下一关
- 失败回到初始关卡
- 图片 / GIF tile 资源
- 背景音乐与消除音效
- 粒子爆炸、连击字、重排动画

本项目不是“只有骨架的空模板”。  
给模型使用时，必须把它当成**已经具备基础可玩循环的 Match-3 no-build 模板**，不要再按“占位实现”描述。

关键词：

- no-build
- 移动端优先
- 配置驱动
- 多媒体 tile
- 多目标关卡
- 强反馈

## 3. 产品定位

### 3.1 目标用户

- 喜欢轻量 Match-3 交换消除的休闲用户
- 偏好短局、即时反馈、低学习成本的移动端用户
- 对图片表情、音效、粒子、连击提示敏感的用户

### 3.2 产品目标

- 在 3 秒内让用户理解“交换相邻元素，完成目标收集”
- 用多目标、步数限制和连锁反馈形成持续动机
- 用媒体化 tile、粒子、重排动画、音频建立商业休闲质感

## 4. 当前核心循环

当前真实单局循环如下：

1. 首次进入游戏，显示开始 overlay。
2. 用户点击开始，进入棋盘。
3. 用户点击或拖拽两个相邻元素，发起交换。
4. kernel 判定是否形成有效匹配：
   - 无匹配：播放 invalid swap 动画
   - 有匹配：进入消除结算
5. 匹配后按顺序结算：
   - 消除匹配块
   - 推进目标进度
   - 增加分数
   - 触发粒子与音效
   - 掉落与补珠
   - 如继续形成匹配，则进入下一次 cascade
6. 若棋盘无可行步，则触发重排动画并重新生成可行棋盘。
7. 若当前目标全部完成，则胜利。
8. 胜利后点击按钮直接进入下一关；失败后点击按钮回到初始关卡并重新弹出开始 overlay。

## 5. 玩法规则

### 5.1 棋盘

- 当前默认棋盘配置来自 `src/config.json`
- 当前可配置行列数
- 当前模板已支持 `5x5`、`8x8` 等尺寸，不要写死成某一个数

### 5.2 交换规则

- 仅允许交换相邻元素
- 必须形成匹配才算有效交换
- 无效交换只播放反馈，不消耗收益

### 5.3 匹配规则

- 当前最小匹配数来自 `gameplay_match_min`
- 支持横向匹配
- 支持纵向匹配
- 支持连锁 cascade

### 5.4 步数规则

- 当前以 `gameplay_move_limit` 为总步数上限
- 每次有效交换后消耗步数
- 步数耗尽且目标未完成则失败

### 5.5 目标规则

当前目标类型只有 1 种：

- `collect`

当前目标对象是“tile 类型”，例如：

- 开心
- 生气
- 难过
- 大笑
- 困惑

不要把当前目标系统描述成别的任务类型。

### 5.6 多目标规则

- 第 1 关：默认单目标
- 第 2 关开始：至少 2 个目标
- 后续关卡：目标数量可继续增长
- 当前 HUD 最多按 4 个目标展示

### 5.7 关卡推进

- 初始关卡来自 `gameplay_level_index`
- 通关后：`levelIndex + 1`
- 失败后：回到初始关卡
- 下一关默认直接开局，不再弹开始 overlay
- 失败重开会重新弹开始 overlay

## 6. 分数与反馈

### 6.1 分数

当前分数由以下部分组成：

- 基础消除得分：`gameplay_score_per_tile`
- 连锁额外得分：`gameplay_score_combo_bonus`

### 6.2 动画反馈

当前已实现：

- swap 动画
- invalid swap 动画
- clear 放大淡出
- 爆炸粒子
- canvas 粒子喷射
- combo 文案
- reshuffle 轮转动画

不要再把这些写成“未来计划”。

## 7. 视觉与媒体规则

### 7.1 背景

当前支持：

- 默认程序绘制背景
- `presentation_background_media`
- `presentation_background_media_type`
- `presentation_background_media_fit`
- `presentation_background_media_position`

优先级：

- 有 background media 时优先使用 media
- 无 background media 时使用程序绘制背景

### 7.2 tile 资源

每个 tile 当前支持：

- `gameplay_tile_<n>_media`
- `gameplay_tile_<n>_asset`
- `theme_tile_glow_<n>`

资源优先级：

1. `media`：上传图片 / GIF 优先
2. 如果没配 `media`：回退到代码生成的默认 SVG

不要说“必须依赖本地 svg 文件”，当前已不是这样。

### 7.3 tile 音效

每个 tile 当前支持：

- `gameplay_tile_<n>_sound`

消除音效优先级：

1. tile 自定义 `sound`
2. 如果该 tile 没配 `sound`：回退到 `presentation_clear_sound`

### 7.4 背景音乐

当前支持：

- `presentation_background_music`
- `presentation_background_music_volume`

行为：

- 用户点击开始后解锁并播放背景音乐
- 背景音乐循环播放

## 8. HUD 与 Overlay 规则

### 8.1 HUD

当前 HUD 包含三块：

- `LEVEL`
- `MOVES`
- `GOAL`

当前 GOAL 面板特性：

- 支持多目标
- 优先显示目标对应资源图标
- 支持上传资源的圆形裁切
- HUD 高度会按目标数量自动增加，避免第二关多目标重叠

### 8.2 Overlay

当前 overlay 支持：

- 动态正文换行
- 动态高度
- 商业化紫色渐变按钮
- 按压反馈

不要把当前 overlay 说成“固定高度、静态按钮”。

## 9. 目录职责

### `src/config.json`

- 单一配置源
- 优先在这里改：
  - tile media
  - tile sound
  - 背景媒体
  - 背景音乐
  - 消除音效
  - 文案
  - 字号
  - 颜色
  - 棋盘参数

### `src/config.js`

- 配置读取层
- 负责平铺 key 聚合
- 负责 tileDefs 构建
- 不负责玩法规则

### `src/kernels/match3Kernel.js`

- 负责：
  - 交换规则
  - 匹配
  - 消除
  - 掉落
  - 补珠
  - 关卡推进
  - 胜负
  - 目标生成

### `src/kernels/systems/goalSystem.js`

- 负责多目标状态
- 负责目标完成判定
- 负责目标快照结构

### `src/renderers/match3/mountMatch3Renderer.js`

- 负责：
  - Pixi 挂载
  - 背景媒体
  - 音频解锁
  - 背景音乐
  - 消除音效触发
  - 布局
  - pointer 输入

### `src/renderers/match3/components/HudView.js`

- 负责 HUD 渲染
- 负责 GOAL 图标与进度显示

### `src/renderers/match3/components/OverlayView.js`

- 负责开始/胜负弹窗
- 负责按钮视觉与按压反馈

### `src/renderers/match3/systems/AnimationController.js`

- 负责：
  - swap
  - invalid swap
  - clear
  - combo
  - reshuffle
  - 粒子与爆炸动画

## 10. 修改优先级

1. `src/config.json`
2. `src/config.js`
3. `src/kernels/match3Kernel.js`
4. `src/kernels/systems/goalSystem.js`
5. `src/renderers/match3/mountMatch3Renderer.js`
6. `src/renderers/match3/components/*.js`
7. `src/renderers/match3/systems/*.js`

判断规则：

- 改文案 / 资源 / 音频 / 字号 / 颜色 / 参数：先改 `src/config.json`
- 配置需要聚合：改 `src/config.js`
- 改规则、关卡、目标：改 kernel
- 改视觉、交互、媒体、音频触发：改 renderer
