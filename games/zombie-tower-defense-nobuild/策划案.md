# zombie-tower-defense-nobuild 策划案

## 1. 项目概述

`zombie-tower-defense-nobuild` 是一套面向移动端竖版场景的 no-build 僵尸塔防模板，当前真实运行内容已经包含：

- 多路线僵尸生成
- 自动炮台购买与升级
- 主基地金币产出与升级
- 副基地血量、防守失败判定与缓慢回血
- 多波次尸潮推进
- 普通怪 / 强化怪 / Boss 区分
- 图片资源与默认几何图形双渲染
- 背景音乐、攻击音效、受击音效
- 顶部 HUD、overlay、tooltip、受击反馈

本项目不是“只有空骨架的塔防模板”。  
给模型使用时，必须把它当成**已经具备基础可玩循环的 no-build 塔防模板**，不要再按“占位实现”描述。

关键词：

- no-build
- 竖版移动端
- 配置驱动
- 多路线尸潮
- 主基地经济
- 副基地防守
- 自动攻击炮台

## 3. 产品定位

### 3.1 目标用户

- 喜欢轻量自动塔防的休闲用户
- 偏好短局、数值成长、明确反馈的移动端用户
- 对图片资源、音效、攻击反馈和升级反馈敏感的用户

### 3.2 产品目标

- 在 5 秒内让用户理解“产金币 -> 买炮台 -> 升炮台 -> 守住副基地”
- 用多路线尸潮和多波次推进建立持续压迫感
- 用资源化怪物、炮台、基地与强反馈 UI 建立 H5 商业休闲质感

## 4. 当前核心循环

当前真实单局循环如下：

1. 首次进入游戏，显示开始 overlay。
2. 用户点击开始，进入防守。
3. 主基地持续产出金币。
4. 用户点击空炮台槽位，弹出 tooltip，确认购买炮台。
5. 已建炮台自动寻找敌人并发射子弹。
6. 用户点击炮台，弹出 tooltip，确认升级炮台。
7. 用户点击主基地，弹出 tooltip，确认升级主基地金币产速。
8. 僵尸从多路线生成，向副基地周围攻击占位点移动。
9. 怪物进入攻击位后持续攻击副基地，副基地在脱战后缓慢回血。
10. 若副基地血量归零，则失败；若所有波次完成且敌人与子弹清空，则胜利。

## 5. 玩法规则

### 5.1 战场结构

当前战场核心实体为：

- 主基地
- 副基地
- 炮台槽位
- 僵尸出生路线
- 多波次尸潮

主基地负责经济，不承担受击判定。  
副基地负责承伤与失败判定。

### 5.2 炮台规则

- 炮台只能在固定槽位购买
- 炮台购买后自动攻击
- 炮台支持升级
- 升级会提升伤害与攻速
- 炮台升级需要消耗金币
- 炮台点击后默认走 tooltip 确认，不用全屏 modal

### 5.3 主基地规则

- 主基地持续产金币
- 主基地支持升级金币产速
- 主基地升级走 tooltip 确认
- 主基地当前不承担生命值系统

### 5.4 副基地规则

- 副基地有血量
- 怪物围绕副基地进行分散占位并攻击
- 不受攻击时可缓慢回血
- 血量归零则失败

### 5.5 敌人规则

当前敌人类型包括：

- `level1`
- `level2`
- `level3`
- `boss`

当前敌人支持：

- 不同资源图
- 不同血量倍率
- 不同伤害倍率
- 不同速度倍率
- 不同尺寸倍率

不要把当前敌人系统描述成“所有怪只有一种模板”。

### 5.6 多路线规则

- 当前支持多路线出生
- 敌人会从多个生成点进入战场
- 当前已支持围绕副基地的分散攻击占位
- 不要再把当前逻辑描述成“所有怪只会正面直冲副基地”

### 5.7 波次规则

- 波次来自 `src/config.json`
- 每波可配置数量、间隔、基础血量、基础速度、基础伤害、奖励、攻击间隔、波后等待
- 胜利条件：所有波次完成且场上没有残余敌人与子弹

## 6. 数值与成长

### 6.1 经济

当前金币来源：

- 主基地持续产出
- 击杀敌人奖励

当前金币消耗：

- 购买炮台
- 升级炮台
- 升级主基地

### 6.2 炮台成长

当前炮台成长主要体现在：

- 伤害提升
- 攻速提升
- 颜色变化

当前升级颜色反馈已实现，不要再说“炮台升级没有视觉差异”。

### 6.3 敌人成长

当前不同波次和不同类型的敌人会使用不同基础数值与倍率。  
如果要调整前期难度，优先看：

- `enemy_types_level1_*`
- `enemy_types_level2_*`
- `waves`

## 7. 视觉与媒体规则

### 7.1 背景

当前支持：

- 默认程序绘制背景
- `assets_background_src`

优先级：

1. 有背景图片时优先用图片
2. 无背景图片时回退到程序绘制背景

### 7.2 实体资源

当前支持资源化的主要实体：

- 普通怪 / 二级怪 / 三级怪 / Boss
- 炮台
- 主基地
- 副基地
- 胜利图

资源优先级：

1. 有 `src` 时优先使用 sprite
2. 没有 `src` 时回退默认 shape

### 7.3 图片缩放规则

- sprite 默认按图片原始宽高比缩放
- 显式配置 `width + height` 时，按给定尺寸显示
- 不要再把当前行为描述成“所有 sprite 都会被强制压成正方形”

### 7.4 音频

当前支持：

- `audio_bgm_*`
- `audio_hit_*`
- `audio_attack_*`

行为：

- 用户首次交互后解锁音频
- 开始游戏后自动播放背景音乐
- 受击和攻击按状态触发音效

## 8. HUD、Overlay 与 Tooltip 规则

### 8.1 HUD

当前 HUD 主要包含：

- 金币
- 波次
- 主基地旁边的等级与金币产速信息

### 8.2 Overlay

当前 overlay 支持：

- 开始 / 胜利 / 失败文案配置化
- 标题 / 正文 / 按钮字号配置化
- 正文自动换行
- 动态高度
- 按钮点击反馈
- 胜利图片展示

### 8.3 Tooltip

当前 tooltip 已用于：

- 购买炮台确认
- 升级炮台确认
- 升级主基地确认

当前 tooltip 支持：

- 长文案换行
- 动态高度
- 近点击点显示

不要再把这些确认交互写成“固定全屏 modal”。

## 9. 目录职责

### `src/config.json`

- 单一配置源
- 优先在这里改：
  - 资源链接
  - 音频
  - 文案
  - 字号
  - 颜色
  - 数值
  - 波次

### `src/config.js`

- 配置读取层
- 负责平铺 key 聚合
- 不负责玩法规则

### `src/kernels/towerDefenseKernel.js`

- 负责：
  - 主循环
  - 波次推进
  - 快照构建
  - 胜负判定
  - 敌人生成参数装配

### `src/kernels/EnemySystem.js`

- 负责：
  - 敌人创建
  - 移动
  - 接敌
  - 攻击
  - 攻击占位

### `src/kernels/TowerSystem.js`

- 负责：
  - 炮台购买
  - 炮台升级
  - 数值成长
  - 自动开火

### `src/kernels/BaseSystem.js`

- 负责：
  - 主基地经济
  - 主基地升级
  - 副基地生命值与恢复

### `src/renderers/mountTowerDefenseRenderer.js`

- 负责：
  - Pixi 挂载
  - HUD
  - overlay
  - tooltip
  - 音频解锁与触发
  - 点击交互
  - 受击反馈

### `src/renderers/RendererFactory.js`

- 负责：
  - shape / sprite 创建
  - 资源预加载
  - tint
  - 等比缩放

## 10. 修改优先级

1. `src/config.json`
2. `src/config.js`
3. `src/kernels/towerDefenseKernel.js`
4. `src/kernels/EnemySystem.js`
5. `src/kernels/TowerSystem.js`
6. `src/kernels/BaseSystem.js`
7. `src/renderers/mountTowerDefenseRenderer.js`
8. `src/renderers/RendererFactory.js`

判断规则：

- 改文案 / 资源 / 音频 / 字号 / 颜色 / 数值 / 尺寸：先改 `src/config.json`
- 配置需要聚合：改 `src/config.js`
- 改波次、敌人生成、占位、胜负：改 kernel
- 改视觉、交互、媒体、音频触发：改 renderer
