# 2048 No-Build 策划案

> 基于 `game-2048-nobuild` 当前实现整理。目标是支持“模板化复用”，在不改玩法核心代码的前提下完成主题与参数定制。

---

## 一、游戏概述

- **游戏名称**：2048（无构建模板版）
- **游戏类型**：数字滑动合并
- **核心体验**：通过滑动合并相同数字，持续追求更高分与更高等级方块
- **单局时长**：约 1~6 分钟
- **目标人群**：休闲玩家、模板复用开发者

---

## 二、设计

### 2.1 核心玩法机制

- **操作方式**
  - 键盘方向键 / WASD
  - 触屏滑动
- **核心循环**
  - 输入方向 -> 全盘移动 -> 相邻同值合并 -> 加分 -> 生成新方块 -> 判断可否继续
- **结束条件**
  - 无可移动空间且无可合并相邻格时结束

### 2.2 子机制列表

1. **移动判定机制**：无位移则判为无效输入
2. **合并得分机制**：合并值累加进分数
3. **合并音效机制**：检测到得分增长时播放合成音效
4. **胜利提示机制**：首次达到 2048 时给出状态提示
5. **失败弹窗机制**：无法移动时显示结束弹窗
6. **最佳分持久化**：通过 localStorage 保存历史最高分
7. **常驻状态提示机制**：状态文案为空时回退显示 `ui_text_status_ready`

### 2.3 正反馈循环

- **即时反馈**：位移动画、合并脉冲、分数变化
- **中期积累**：高数值方块逐步出现，盘面策略增多
- **长期驱动**：最高分刷新与挑战更高等级

### 2.4 界面交互逻辑

- 页面状态：Loading（隐式）-> 开始弹窗 -> 对局中 -> 结束弹窗
- 交互区：
  - 棋盘区域（核心玩法）
  - 分数区 / 最高分区
  - 新游戏按钮
  - 弹窗操作按钮（开始/重开）

## 三、开发

### 3.1 功能点统计

| 模块 | 功能 | 技术要点 |
|---|---|---|
| 启动模块 | 挂载内核与渲染器 | ESM 入口 |
| 规则内核 | 2048 合并逻辑、得分与胜负 | 状态机 + 网格规则 |
| 渲染模块 | 棋盘绘制、动画与输入映射 | Pixi.js |
| 配置模块 | 参数、文案、主题颜色读取 | 平铺 config + 兼容读取 |
| 存储模块 | 最佳分持久化 | localStorage |

### 3.2 架构简述

- `src/kernels/game2048Kernel.js`：纯规则
- `src/renderers/game2048/mountGame2048Renderer.js`：纯表现
- `src/config.json`：平铺配置源
- `src/config.js`：配置读取与编辑权限辅助

## 四、美术与UI

- 风格：简洁扁平、复古棋盘感
- 配色通过 `theme_*` 配置驱动
- UI 以竖屏优先，兼容桌面与移动端
- 弹窗与按钮可在不改逻辑前提下通过主题色和文案定制

## 五、音频（当前实现 + 扩展）

当前模板已内置合并音效：

- `asset_audio_merge`：发生合并（分数增长）时播放

扩展建议（可新增）：

- `asset_audio_bgm`
- `asset_audio_move`
- `asset_audio_gameover`

音频接入保持在 renderer 层，不进入 kernel。

## 六、插件扩展与接入规范

### 6.1 现有插件

- `pixi.js` 通过 import map 直接引入

### 6.2 新增插件流程

1. 在 `index.html` 的 import map 添加 CDN 映射
2. 在 `config.json` 添加 `plugin_xxx_*` 平铺配置
3. 通过 `getSetting("plugin_xxx_enabled", false)` 控制开关
4. 按职责接入：
   - 规则插件 -> kernel
   - 表现插件 -> renderer

---

## 七、模板复用建议

1. 第一阶段只改 `config.json`（文案 + 主题 + 参数）
2. 第二阶段按需调整输入体验与动画参数（仍优先配置）
3. 必须保持“kernel 纯规则 / renderer 纯表现”边界
4. 每次改动后验证：移动、合并、得分、胜负、重开、最高分持久化、合并音效、常驻状态提示
